# Spec 05 — Markdown parsing and highlighting (`form-core::markdown`)

> **Workstream W5.** Owns `core/crates/form-core/src/markdown/`. Produces the typed block
> tree that `FormMarkdown` (W11) renders. Parsing and highlighting live in Rust so three
> future platforms share one implementation; **colors never appear here** — only scope names.

## 1. API

```rust
pub fn parse(text: &str) -> MarkdownDoc;
pub fn parse_streaming(text: &str, complete: bool) -> MarkdownDoc;
```

`complete: false` means the text may end mid-construct. Unterminated fences, half-written
tables, dangling emphasis and incomplete links must degrade to something renderable rather
than disappearing or flickering the whole document (F7.3). The last block carries
`partial: true` so the renderer can suppress trailing chrome (e.g. a copy button on a code
block still being written).

## 2. Block tree

```rust
#[serde(tag = "type", rename_all = "camelCase")]
pub enum MarkdownBlock {
    Paragraph { spans: Vec<Span> },
    Heading { level: u8, spans: Vec<Span>, anchor: String },
    CodeBlock { language: Option<String>, code: String,
                tokens: Vec<CodeToken>, partial: bool },
    List { ordered: bool, start: u64, tight: bool, items: Vec<ListItem> },
    Quote { blocks: Vec<MarkdownBlock> },
    Table { align: Vec<ColumnAlign>, header: Vec<Vec<Span>>, rows: Vec<Vec<Vec<Span>>> },
    Rule,
    Image { url: String, alt: String, title: Option<String> },
    Html { raw: String },          // rendered as escaped plain text; never executed
    FootnoteDef { label: String, blocks: Vec<MarkdownBlock> },
}

pub struct ListItem { pub checked: Option<bool>, pub blocks: Vec<MarkdownBlock> }

#[serde(tag = "type", rename_all = "camelCase")]
pub enum Span {
    Text { text: String },
    Emphasis { spans: Vec<Span> },
    Strong { spans: Vec<Span> },
    Strike { spans: Vec<Span> },
    Code { text: String },
    Link { url: String, title: Option<String>, spans: Vec<Span> },
    FootnoteRef { label: String },
    Break { hard: bool },
}

pub struct CodeToken { pub start: u32, pub len: u32, pub scope: String }
```

Every block carries a stable `id` derived from `(index, content hash)` so SwiftUI's
`ForEach` diffing keeps identity across streaming re-parses and does not rebuild the whole
transcript per token.

## 3. Parsing

`pulldown-cmark` with GFM extensions on: tables, strikethrough, task lists, footnotes,
autolinks. Smart punctuation **off** — code and technical prose must survive verbatim.

Sanitize: raw HTML is captured as `Html { raw }` and rendered as escaped text; no HTML is
ever interpreted. Link URLs are validated — allow `http`, `https`, `mailto`, `file`; anything
else (notably `javascript:`) is downgraded to plain text (F7.5 is a rendering concern, this
is the safety half).

## 4. Highlighting

`syntect` with the default syntax set, but emit **scope names with byte ranges**, never
colors — `FormDesign`'s `SyntaxTokens` maps scope → color (spec 08 §2.5). Ranges are in
**UTF-16 code units** so Swift can apply them to `AttributedString` without re-encoding;
document this and test it with emoji and CJK.

Language resolution: fence info string → syntect token, with aliases (`ts`, `tsx`, `js`,
`jsx`, `sh`, `zsh`, `yml`, `objc`, `c++`). Unknown or absent language yields one `plain`
token spanning the code. A `diff` fence gets line-level `markup.inserted` /
`markup.deleted` scopes.

Cap highlighting at 200 KB per block and 5000 lines; beyond that emit a single `plain`
token — a runaway paste must not stall the stream.

## 5. Performance

`parse_streaming` is called on a debounce during streaming, on documents that grow token by
token. Budget: **16 ms for a 120-block, 60 KB document**, and re-highlighting only blocks
whose content hash changed. Memoize by block hash in an LRU (capacity ~512) inside the
module.

## 6. Done when

  incremental parses of a growing document; the 16 ms budget as a `#[test]` with a generated
