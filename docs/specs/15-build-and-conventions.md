# Spec 15 — Build, layout and conventions

> Written by W0. Read this before writing code in any workstream.

## 1. Repository layout

```
form/
  Makefile                    # the only entry point you need
  docs/PRD.md  docs/specs/
  core/                       # Cargo workspace
    Cargo.toml
    include/form.h            # generated by cbindgen, committed
    crates/form-core/         # W1 app+store, W2 harness, W3 stats,
                              # W4 catalog/settings/context, W5 markdown
    crates/form-ffi/          # W6
    crates/form-cli/          # W6
    tests/fixtures/protocol/  # generated by `form-cli protocol-dump`
  app/                        # SwiftPM package
    Package.swift
    Sources/FormFFI/          # W7 — module map over core/include + libform_ffi.a
    Sources/FormCore/         # W7
    Sources/FormDesign/       # W8
    Sources/FormMarkdown/     # W11
    Sources/FormUI/
      Shell/ Sidebar/         # W9
      Chat/                   # W10
      Home/                   # W12
      Preferences/ Attachments/  # W13
      Commands/               # W14
    Sources/form/             # W9 — @main, App, menus
    Tests/
  scripts/build-app.sh        # assembles form.app
```

**Directory ownership is exclusive.** If your work requires editing a file another
workstream owns — including `Package.swift`, `core/Cargo.toml`, `protocol.rs`,
`Protocol.swift` — do not edit it. Report what you need; the orchestrator makes the change.

## 2. Build

```bash
make            # rust (release) + swift build + assemble app/build/form.app
make debug      # debug variants
make test       # cargo test + swift test + protocol fixtures
make lint       # cargo fmt --check, clippy -D warnings
make headers    # regenerate core/include/form.h
make run        # build + open form.app
```

The Rust core builds as a universal static library (`aarch64-apple-darwin` +
`x86_64-apple-darwin`, `lipo`'d) for release; debug builds host-arch only for speed.

No `.xcodeproj` is committed. `xcodegen` can produce one on demand for debugging in Xcode;
SwiftPM is the source of truth.

## 3. Conventions

### Rust
- Follow [`pi-rs/AGENTS.md`](../../../pi-rs/AGENTS.md) verbatim for anything on the boundary:
  no lifetimes or generics in public signatures, owned `'static + Send + Sync` types,
  `#[serde(rename_all = "camelCase")]`, flat error enums with `code() -> &'static str`,
  never leak `anyhow` across a crate boundary, `Option<AbortSignal>` on long-running calls.
- `cargo fmt` and `cargo clippy -p <crate> -- -D warnings` must be clean before you report
  done.
- Comment the *why* of non-obvious decisions only. Do not narrate the obvious.

### Swift
- Swift 6 language mode, strict concurrency. UI types are `@MainActor`; protocol types are
  `Sendable`.
- `@Observable` (not `ObservableObject`) for stores.
- No force-unwraps outside tests. No `print` — use `Log` from `FormCore`.
- Every view gets a `#Preview` that works against `MockTransport` with **no Rust build**.
- No color, font, spacing, radius or duration literals outside `FormDesign` (spec 08 §5).

### Both
- Match the surrounding code's density and idiom. Small, focused files.
- Tests live next to what they test and are part of "done", not a follow-up.

## 4. Reporting

When a workstream finishes, report: what was built, the exact commands run and their
results, anything left undone and why, any assumption made, and any change you needed in a
file you do not own. Do not report done with failing tests or a dirty clippy run.
